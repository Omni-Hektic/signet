## What the Detectors Find

### SIG-01 Findings

**Title**: Missing zero-address check on ecrecover() return value

**Severity**: HIGH  
**Confidence**: HIGH (when Semgrep + Slither + LLM agree)

**Proof example**:
```solidity
address signer = ecrecover(messageHash, v, r, s);  // Line 42
require(signer == owner, "Invalid signature");      // Line 43 — ❌ No address(0) check
```

**Fix**:
```solidity
address signer = ecrecover(messageHash, v, r, s);
require(signer != address(0), "Invalid signature");  // ✅ Add this
require(signer == owner, "Signature mismatch");
```

### SIG-03 Findings

**Title**: Missing chain-id / domain-separator binding in signature digest

**Severity**: HIGH  
**Confidence**: HIGH (when Semgrep + Slither + LLM agree)

**Proof example**:
```solidity
bytes32 digest = keccak256(abi.encodePacked(
    owner,
    spender,
    value,
    nonce[owner],
    deadline
    // ❌ Missing: block.chainid and address(this)
));
address signer = ecrecover(digest, v, r, s);
```

**Fix**:
```solidity
bytes32 domainSeparator = keccak256(abi.encode(
    EIP712DOMAIN_TYPEHASH,
    keccak256("TokenName"),
    keccak256("1"),
    block.chainid,      // ✅ Add this
    address(this)       // ✅ Add this
));
bytes32 digest = keccak256(abi.encodePacked(
    "\x19\x01",
    domainSeparator,
    keccak256(abi.encode(...))
));
```

## Known Limitations

### Semgrep Rules
- ⚠️ **Pattern-based**: May miss non-standard encodings (e.g., keccak256(abi.encode()) vs keccak256(abi.encodePacked()))
- ⚠️ **False positives**: ~5% (e.g., contracts that intentionally use address(0) as sentinel value)
- ⚠️ **Encoding variants**: May miss: `abi.encodePacked()` with multi-line args, dynamic splicing, nested keccak256

### Slither Detectors
- ⚠️ **Compilation required**: Needs solc to parse contracts
- ⚠️ **External call side effects**: May miss cases where external function modifies signer value
- ⚠️ **Proxy/inheritance**: May not trace through abstract contracts (conservative)

### LLM Synthesis
- ⚠️ **Context limits**: Very large contracts (>500 lines per function) may exhaust agent context
- ⚠️ **Reasoning time**: ~30-60 seconds per finding (expensive for high-volume audits)
- ⚠️ **Non-deterministic**: Same code analyzed twice may produce slightly different findings (model temperature)

**Mitigations**:
- Use Phase 1 (Semgrep) for fast screening on large codebases
- Use Phase 2 (Slither) to confirm suspicious findings
- Use Phase 3 (LLM) only on high-confidence findings (reduce cost/time)
